# 日本光電 `.EEG` のブロックレイアウト: `wfmblock` と `extblock`

`PDL::EEG::IO::NihonKohden` が日本光電 `.EEG` からチャンネルとサンプルをどう
特定するかのリファレンス。以下のオフセットはすべてリーダーが実際に使っている
値で、実記録および MNE-Python の `read_raw_nihon` と突き合わせて確認済み。

## 2つのレイアウトとは

`.EEG` は波形を2種類の内部レイアウトのどちらかで格納する。名称はリーダー独自で、
チャンネルテーブルを保持する構造にちなむ:

- **`wfmblock`**（波形ブロック）— 旧レイアウト。チャンネルテーブルは波形ブロック
  の**内部**、サンプル列の直前にある。EEG-1100 系（および QI-403A, EEG-2100,
  DAE-2100D）が使用。
- **`extblock`**（拡張ブロック）— 新レイアウト。チャンネルテーブルはファイル先頭
  付近のポインタから辿る拡張ブロック連鎖の中にあり、サンプル列は複数の時間
  セグメントに分かれることがある。EEG-1200 系が使用。

レイアウトは**ファイルに書かれた形式署名の属性であって、物理的な記録機種名では
ない**。実機 EEG-1290 は署名 `EEG-1200A V01.00`（`extblock`）を書き、EEG-1214 は
`EEG-1100C V01.00`（`wfmblock`）を書きうる。したがって分岐は署名で行い、機種名では
判断しない。

## レイアウト分岐（`nk_layout`）

ファイルオフセット `0x0000` の16文字署名が、次の順でレイアウトを決める:

1. `%FORMAT_LAYOUT` に完全一致 → 権威（`how = table`）。
2. 構造フォールバック: `ext_address`（`u32LE @ 0x03EE`）が非0 → `extblock`、
   0 → `wfmblock`。検証済みの判別子（1100C = 0, 1200A ≠ 0）。
3. 名前系統（`EEG-11*` → `wfmblock`, `EEG-12*` → `extblock`）は構造判定の照合と
   食い違い時の警告にのみ使用。
4. `EEG-`/`QI-`/`DAE-` で始まらない署名 → `undef`（非NKファイルを誤読しないよう
   停止する）。

`nk_layout` は `($signature, $layout, $how)` を返し、`$how` にどの規則が効いたかが
入る。

## 共通ヘッダ（両レイアウト）

- 署名: `0x0000` から16バイト。
- `ext_address`: `u32LE @ 0x03EE`（0 ⇒ `wfmblock`、非0 ⇒ `extblock`）。
- コントロールブロック: 個数 `u8 @ 0x0091`、アドレス `u32LE @ (0x0092 + i*20)`。
- 先頭のデータ／波形ブロックアドレス: `u32LE @ (control_addr + 18)`。

## `wfmblock`（EEG-1100 系）

チャンネルテーブルとサンプルは波形ブロック内にある。ブロックアドレスからの相対:

| オフセット      | 意味                                                        |
|-----------------|-------------------------------------------------------------|
| `+0x00`         | `0x01` ブロック種別                                         |
| `+0x01..+0x10`  | ASCII 時刻文字列（`"TIMEhhmmss..."`, 16バイト）             |
| `+0x14..+0x19`  | BCD タイムスタンプ `YY MM DD HH MM SS`                      |
| `+0x1A..+0x1B`  | `u16LE`、下位14ビット = サンプリング周波数                  |
| `+0x26`         | `u8` = `n_ch_entries`（有効な EEG／生理チャンネル数）      |
| `+0x27..`       | チャンネルテーブル: 10バイト × `n_ch_entries` レコード      |
| `+0x27 + n_ch_entries*10` | データ先頭（33ch なら `+0x171`）                 |

サンプル列は `n_ch_entries + 1` チャンネル（末尾にゼロ埋め1本）。

### レコード構造と電極コード

各10バイトレコードは**先頭バイトが電極コード**で、レコード末尾2バイトが固定
フッタ `0x10 0x05`:

```
+0  ch_code   (1バイト)  <- 電極コード
+1 .. +7      (ペイロード)
+8  0x10                 (末尾フッタ。ヘッダではない)
+9  0x05
```

したがってチャンネル `i` のコードは `u8 @ (block + 0x27 + i*10)`、サンプル列は
最終レコード直後の `block + 0x27 + n_ch_entries*10` から始まる。仕様上のデータ
先頭 `+0x171` はレコード先頭 `+0x27` とだけ整合する（`0x27 + 33*10 = 0x171`）。
これがレコード先頭位置を確定させる。

### 修正済みの1レコードずれ（ラベルのみ）

旧コードは `0x10 0x05` を**先頭**ヘッダと誤認し、コードを `+0x2F + i*10 + 2`
（= `+0x27 + (i+1)*10`、**次**レコードの先頭バイト）から読んでいた。`.21E[code-1]`
補正と組み合わさると、連続する 10-20 のコード `1..19` ではズレと `-1` が相殺し、
その19本は正しく見えた。しかしコードが飛ぶ補助チャンネル（例
`…20, 23, 24, 25, 26, 27, 45…`）では全部が隣の電極名に載り、`E` が落ち、`X1` が
`EtCO2` と表示され、`DC06` が落ち、`DC32` が湧く、といった症状になっていた。

誤っていたのは**ラベルだけ**で、サンプル列は常に正しく読めていた。よって既存の
19ch 10-20 の ERP／LORETA 解析はこのバグの影響を受けない。修正はコードをレコード
先頭から読む:

```perl
push @ch_indices, _read_u8($fh, $addr + 0x27 + $i * 10) + 1;
```

## `extblock`（EEG-1200 系）

> 深掘り（eb 連鎖の算出、ADC ゲイン、セグメントヘッダ、実例）は
> [`NK_extblock.md`](NK_extblock.md) を参照。

チャンネルテーブルは拡張ブロック連鎖にあり、サンプル列は複数の時間セグメントを
含みうる。

チャンネル情報ブロックへの到達:

- `ext_address = u32LE @ 0x03EE`（非0）。
- `eb2 = u32LE @ (ext_address + 18)`。
- `eb3 = u32LE @ (eb2 + 20)` — チャンネル情報ブロックの先頭。

チャンネル情報ブロック内:

| オフセット（`eb3` から） | 意味                                             |
|--------------------------|--------------------------------------------------|
| `+68`                    | `u16LE` = 有効チャンネル数。`n_ch = それ + 1`（末尾 STIM）|
| `+72..`                  | チャンネルテーブル: ストライド10バイト           |
| `+72 + i*10`             | `u16LE` = チャンネル `i` の電極コード            |

チャンネル情報ブロックの長さは `hdr_len = 72 + (n_ch-1)*10` バイト（例 442）で、
最初のサンプルはその直後 `eb3 + hdr_len` から始まる。

### セグメント

`extblock` は単一連続のデータ領域ではない。記録の中断ごとに、記録機は
チャンネル情報ブロックの複製（`eb3` のものとタイムスタンプ以外はバイト一致）を
サンプル列に書き込んでから続行する。埋め込みヘッダはサンプル境界に整列していて
識別可能:

```
+0x00        0x01                      ブロック種別
+0x01..+0x04 "TIME"
+0x12,+0x13  0x02 0x02                 バージョン
+0x14..      "YYYYMMDDHHMMSS" (ASCII)  当該セグメントの開始時刻
+0x44        u16 = n_ch - 1            チャンネル数（一致必須）
+0x48..      再びチャンネルテーブル
```

リーダーはこれらのヘッダを検出して読み飛ばす。（単一ブロックが EOF まで続くと
仮定していた旧コードは、埋め込みヘッダを約5.8サンプルの EEG として読み、中断ごと
にチャンネル位相が `hdr_len % stride` バイトずれ、サンプル数も過大報告していた。
修正済み。）

## 共通: 電極コード → 名前（`.21E`）

両レイアウトともチャンネルごとに電極コードを持ち、これは **`.21E` の
`[ELECTRODE]`／`[REFERENCE]` テーブルへの 0-based インデックス**。リーダーは
`ch_indices` にコードを `+1`（1-based）で保持し、共通の `.21E[code-1]` で名前を
引く。これは生バイトを 0-based テーブルにそのまま当てる MNE-Python
`read_raw_nihon` と数値的に一致する。

`wfmblock` は全チャンネル µV。`extblock` はファイルに保存されないハードウェア
固定の ADC ゲインで µV に換算する。

## DC トリガ番号の世代差

DC チャンネルの番号は**形式署名**で決まり、レイアウトでは決まらない:

- `wfmblock` / EEG-1100 → `DC03`–`DC06`
- `extblock` / EEG-1200 → `DC01`–`DC04`

いずれも下記の検証ファイルに現れ、ベンダ書き出しと一致する。

## 参照チャンネルの命名（`$` → `_ref`）

日本光電の `$` 接頭の参照名（`$A1`, `$A2`）は、Perl・ファイル名として安全な
`_ref` 接尾（`A1_ref`, `A2_ref`）に正規化する。EDFBrowser は生の `$A1`/`$A2` を
そのまま残すが、指す物理チャンネルは同一。データの差ではなく命名規約の差。

## 検証

- **`wfmblock`** — `YJ0394RY.EEG`（EEG-1100C）: 1レコードずれ修正後、チャンネル列
  が EDFBrowser の書き出しと1本ずつ一致
  （`… Pz, E, A1, A2, vEOG, hEOG, X1, DC03–DC06, BN1, BN2 …`）。
- **`extblock`** — `JJ0090J6.EEG`（EEG-1200A, EEG-1290 / JE-92NX, 37ch）が
  EDFBrowser と全37チャンネル一致
  （`… X1, nose, lm, rm, DC01–DC04, BN1, BN2, $A1/$A2, COM`）。`IJ0200S9.EEG`
  （EEG-1200C, マルチセグメント）も正しいチャンネル順で読める。
- いずれも MNE-Python `read_raw_nihon` と整合。

EDFBrowser との唯一の差は参照名の表記（`A1_ref`/`A2_ref` 対 `$A1`/`$A2`）で、
これは上記 `_ref` 正規化による。
